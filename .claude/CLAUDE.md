## Как подавать — стиль проверен на EST/OS

- **Язык простой.** Термин — только если без него никак, и сразу расшифровать.
  Без тяжёлых слов ради тяжёлых слов. Флаги и команды — с объяснением, что делает каждая.
- **Идти по пунктам методички, теорию объяснять по ходу.** Не теория блоками «с нуля»,
  а: *пункт работы → что набрать в терминале → что это значит → что увидишь в листинге*.
- **Не проверять до обсуждения.** «Проверь себя» — только когда пользователь готов.
- **Один ответ = один смысловой блок.** Закончил — стоп, ждать реакции.
- Всё на **русском**. Тон честный, без мотивашек и похвалы за вопросы.
- Термины: русский + English в скобках при первом упоминании. В конце каждого конспекта —
  раздел `## Ключевые термины (English)`.
- Ссылки не генерировать — только названия.

## Формат работы по лабе (согласовано 2026-10-01)

- **Команды компиляции в основном запускает пользователь** на своей машине — это и идёт
  в отчёт (листинги, скриншоты, размеры). Claude ведёт по шагам и объясняет.
- **Claude тоже может скомпилировать сам** — для сверки листингов и точных объяснений
  (рецепт — в разделе «Софт»). Результаты своей компиляции помечать как справочные.
- Пользователь запускает у себя в **обычном терминале** (не через `!` внутри Claude Code —
  там та же песочница) и присылает вывод или скриншоты.

## Цикл лабы

1. Требования лежат в `материалы/Требования лабораторная №N.docx` (текст извлекать через
   `python` + `zipfile`, см. ниже). Разобрать порядок выполнения и требования к отчёту.
2. Claude пишет `labs/Лабораторная работа №N/plan.md` — пункты по порядку, команды, флаги,
   на что смотреть. По ходу — конспекты `knowledge-base/NN-*.md` простым языком.
3. Идём по пунктам. Пользователь запускает у себя, присылает листинги/вывод — Claude разбирает.
4. Отчёт пользователь собирает **в Word** (`ПобирчевНА ЛабN.docx`). Claude готовит структуру,
   тексты, таблицы, выводы и проверяет готовый `.docx` (картинки — `word/media/`, текст —
   `word/document.xml`).
5. Перед защитой — `labs/Лабораторная работа №N/zashchita.md`, простым языком.
6. Конец сессии — обновить `knowledge-base/00-progress.md`, `journal.md`, статус в `plan.md` лабы.

## Софт

- **Компилятор ЛР-1 — GCC 15.2.0**, `C:\mingw64\bin\gcc.exe` (настоящий GCC).
  Внимание: первый `gcc` в `PATH` — это `C:\llvm-mingw-...\bin\gcc.exe`, а он **clang**.
  Для gcc вызывать полный путь или ставить `C:\mingw64\bin` первым в `PATH`.
- Рядом: Clang/LLVM 20 (`C:\llvm-mingw-20250417-msvcrt-x86_64\bin`), Git 2.45.
- Binutils при GCC: `objdump`, `size`, `nm` в `C:\mingw64\bin`.
- **Компиляция на стороне Claude** (sandbox блокирует запуск `cc1.exe`):
  в вызове Bash — `dangerouslyDisableSandbox: true`, затем
  `export PATH="/c/mingw64/bin:$PATH"` и запускать из `/c/mingw64/bin`
  (иначе `cc1.exe` не находит свои DLL → exit 127/1 без текста ошибки).
- Основные флаги: `-S` ассемблерный листинг, `-O0/-O1/-O2/-O3` скорость, `-Os` размер,
  `-masm=intel` синтаксис как в методичке, `-fverbose-asm` комментарии к строкам.
- Текст из `.docx`: `python` + `zipfile` → `word/document.xml`, выдёргивать `<w:t>…</w:t>`.
  Писать результат в файл (консоль рубит кириллицу в выводе), потом читать файл.
